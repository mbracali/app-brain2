# Feedbacks — content guideline

> [!Note] This is a **guideline**, not a strict template.
> Describes the content that lives in `02_PERSONAL/02_03_FEEDBACKS/` and suggests common shapes. Adapt to the actual content.

Captures explicit feedback Marcelo gives or receives. Not meeting summaries — those belong elsewhere.

## What goes here

- **Feedback received** — comments, criticism, praise, suggestions Marcelo got from someone else.
- **Feedback given** — feedback Marcelo delivered to someone else.
- Each feedback is a small entry: when, who, what was said, what to do about it.

## Suggested shapes

A common pattern: one file per source (a manager, a peer, a mentor) with a chronological log of feedback entries. Or one file per period (e.g. annual reviews).

Inside the file, each feedback entry typically has:

- A header with date and source: `## YYYY-MM-DD — From [[PERSON_FILENAME|Display Name]]` (or "From self" / "Given to ...").
- The feedback content as prose or a short table for itemized points.
- An optional `Suggestions / follow-ups` section listing concrete actions.

## Filenames

Human-readable. Examples: `Feedback - Carlos (manager).md`, `Annual review - 2025.md`, `Self-reflection log.md`.

## Cross-references

People → `01_PEOPLE/index.md`. Always link the feedback's source/recipient to their profile when one exists. Otherwise render as plain text.
